# RFC-0002 — CDL v0.2

> **Names referenced but not linked** — `Rule #N` and `Axiom A-N` are Archstone's internal
> constitution; `ADD-NN`, `RQ-NNN`, the Charter, the Model-Breakers study and the four-domains
> study are its architecture, research and language-engineering series. They are cited so a claim
> here can be traced to where it was decided; those documents are not published. Nothing here
> depends on reading them.


> This document describes the current understanding of the problem. It is expected to evolve as new evidence becomes available.

**Status:** Accepted (2026-07-14, with amendments) · **Kind:** Type A — Language RFC (Charter §3)
**Role:** this RFC is the **Rationale** — it argues *why* each primitive exists. The strict, normative grammar is the [CDL Specification](../cdl-specification.md). (The split mirrors Rust's *Reference* vs *RFC*: spec short, motivation complete.)
**Bar:** near-impossible. Every primitive here carries a Concept dossier and pays the Primitive Budget.
**Freeze basis:** all primitives met the three freeze gates (Charter §2.1) — need proven, form reduced, attacks quiet.

---

## 1. Summary

CDL v0.1 (RFC-0001) shipped `id`,
`description`, `input`/`output`, `policies`, `provider`. Two waves of adversarial
research — the four-domains study,
the 10-domain Model Breakers catalogue, and
RQ-002 — proved a small set of additions
**necessary** and, crucially, showed that everything *else* people reach for
(`preconditions`, `guarantees`, `signature`, `emits`, streaming, a trigger field, a
state-machine DSL) **reduces into existing constructs or belongs to another layer**.

CDL v0.2 promotes exactly the proven set to **Experimental** (Rule 11):

| Primitive | Kind | Status target |
|---|---|---|
| `effect` | capability field (required) | Experimental |
| `failures` | capability field (optional) | Experimental |
| `ref` | input field form | Experimental |
| `lifecycle` | capability field (optional) | Experimental |
| `resource` (`*.resource.yaml` `fields:`) | manifest kind | Experimental |
| `money`, `time-slot`, `quantity`, `enum`, `date` | semantic types → **RFC-0005** | Experimental |

**Accepted does not mean Canonical.** The schema (`cdl.schema.json` v0.2) and
`examples/` update as the **rollout step** (§6, ADR-0001
process); until the compiler and real manifests exercise them, these primitives are
**Experimental**, not frozen (Rule 11).

---

## 2. The grammar

The normative grammar — document root, field forms, manifest kinds, conformance —
is the **[CDL Specification](../cdl-specification.md)**. This RFC does not
restate it. In one line, v0.2 adds to the capability root: a **required** `effect`,
optional `failures` and `lifecycle`, a `ref` field form, and a `*.resource.yaml`
manifest kind. Everything below argues *why*.

## 3. Concept dossiers

Each primitive is argued as a research object. Motivation, counterexamples, and
rejected alternatives were established in the linked research; dossiers cite rather
than re-derive.

### 3.1 `effect`

- **Definition.** A required enum on every capability: `read | write | irreversible`,
  describing what invoking it does to the world.
- **Motivation.** All 4 study domains + the 10 breaker domains: an agent must treat
  `tourism.search` and `banking.initiate-transfer` differently, and v0.1 gives no
  signal. Compiles to MCP `readOnlyHint`/`destructiveHint`.
- **Examples.** `read`: `banking.quote-transfer`, any search. `write`: `tourism.book`
  (compensable). `irreversible`: `banking.initiate-transfer`.
- **Governed by an axiom (not defined here).** This primitive is bound by
  Constitution Axiom A-1: *`effect` describes the
  reversibility of invoking a capability, not of its business consequences.* A
  cancellable order is `write` though its fill is irreversible; a fill-or-kill order
  is a separate `irreversible` capability. The RFC *uses* the axiom; it cannot
  redefine it.
- **Counterexamples.** Not for infrastructure (login, logging — those are not
  capabilities). Not a fourth value: trading attack proved three suffice.
- **Rejected alternatives.** A `guarantees` bag (ADR-0004 D-3) — `idempotent` folds into `effect`/retry; `auditable` is platform-wide; `transactional` is Execution-model.
- **Evidence.** *Minimality:* Banking dies without it (cannot distinguish read from irreversible transfer). *Completeness:* not falsified across 14 domains.
- **Known limitations.** Static per capability; dynamic reversibility (trading) is modeled as distinct capabilities, not a dynamic `effect`.

### 3.2 `failures`

- **Definition.** Optional map: kebab-case token → one-line description of a
  **business** failure state. Capability-scoped.
- **Motivation.** All domains; mandated by Constitution Rule 6.
  `insufficient-funds`, `slot-taken`, `out-of-stock` are semantics an agent plans
  around, not HTTP codes.
- **Examples.** `banking.initiate-transfer`: `insufficient-funds`, `limit-exceeded`.
  `logistics.allocate-slot`: `slot-taken`.
- **Counterexamples.** Not HTTP status; not per-item batch results (those are
  **output data** — a `collection` of results, MODEL_BREAKERS K); no codes, severities, or retry hints (Execution-model drift).
- **Rejected alternatives.** `preconditions` (ADR-0004 D-1) — pre-conditions reduce **to** `failures`, three times over (RQ-002 §7.2).
- **Evidence.** *Minimality:* Banking dies without it. *Completeness:* absorbed every contention/rejection outcome across 10 breaker domains.
- **Known limitations.** No *proactive* affordance planning — an agent learns illegal moves by trying (the recurring `preconditions` tension, still reactive-only).

### 3.3 `ref`

- **Definition.** A third input-field form — `ref: <Resource>` — a reference **by
  identity**, distinct from `type: <Resource>` (a representation, used in output).
- **Motivation.** Banking, healthcare, commerce: v0.1 cannot distinguish "point at a
  Booking" (input) from "return a Booking" (output).
- **Examples.** `tourism.book` input `accommodation: { ref: Accommodation }`; output
  `booking: { type: Booking }`.
- **Counterexamples.** Not a URL or DB key (that is Connector); a `ref` is a domain
  identity, resolved by the runtime.
- **Rejected alternatives.** Overloading `type` for both roles (the v0.1 ambiguity, G4).
- **Evidence.** *Minimality:* Commerce dies without it (`OrderLine` needs
  `product: { ref: Product }` distinct from returning an `Order`). *Completeness:* not falsified.
- **Known limitations.** Convention (`ref` in input, `type` in output) is not
  machine-enforced beyond the schema shape.

### 3.4 `lifecycle`

- **Definition.** Optional enum, default `stable`:
  `experimental | beta | stable | deprecated | retired`. Full design:
  capability-lifecycle.md.
- **Motivation.** Any large org: no safe way to hide `experimental` from agents.
- **Counterexamples / rejected.** **`visibility`/audience is rejected** — "who may
  call it" is Policy (Manifesto P6); lifecycle is a *business fact*, the two axes must not fuse.
- **Evidence.** *Minimality:* a large catalog dies without it (unsafe agent
  exposure). *Completeness:* one enum covered every readiness state seen.
- **Known limitations.** Successor/deprecation relations are a **catalog** concern,
  not on the capability (P7).

### 3.5 `resource` (a **manifest**, not a primitive)

- **Two things, kept apart** (per [Spec §3](../cdl-specification.md)): the
  language *primitive* is the **Resource Reference** (`ref`, §3.3); the *manifest* is
  the **Resource Definition** (`*.resource.yaml`). The compiler resolves the first
  during capability compilation and loads the second as a named type. This dossier is
  about the Definition.
- **Definition.** `*.resource.yaml` declaring `name` (domain-qualified),
  `description`, and `fields` — reusing the capability field grammar verbatim.
- **Motivation.** All domains name resources; commerce forces it (`OrderLine` is
  structured input). RQ-002: resource **state
  is a `status` field + `date` fields**, not a state-machine DSL.
- **Counterexamples / rejected.** **No `states:`/`transitions:` block** — the state
  machine is *derived* from capabilities, transitions live in `effect`+`input`/`output`,
  pre/post-state reduce to `failures`/output (RQ-002 §7, ADR-0004 D-2).
- **Evidence.** *Minimality:* Commerce dies without structured resources.
  *Completeness:* candidates 2–4 all reduced into "fields only" under five attacks.
- **Known limitations.** Concurrency/versioning of resource state is Execution-model, not declared here.

### 3.6 Semantic types — moved to their own RFC

The v0.2 type additions (`money`, `time-slot`, `quantity`, `enum`, `date`) live in
the **Semantic Type System, RFC-0005** — an
independently-versioned catalog, so a future type (`percentage`, `email`) never
reopens this grammar RFC.

### 3.7 Resource-name qualification (P-7) — ratified 2026-07-16

Resource names are **domain-qualified** (`tourism.Accommodation`), paying
SD-2. §3.6 stated this as a fact; this
subsection ratifies the full resolution rule as **D-8** (below) — the
algorithm was designed and shipped (four-domains study P-7,
ADD-11, `resolve.ts`,
commit `293fbdd`) before this RFC formally adopted it; this closes that gap.

**The rule:**

1. A resource name may be written **qualified** (`tourism.Accommodation`) or
   **bare** (`Accommodation`).
2. A bare name is shorthand for the **referring capability's/resource's own
   domain** — `Stay` inside a `tourism.*` capability resolves to
   `tourism.Stay`. It is **not** a global lookup.
3. **Cross-domain references must be qualified.** A capability in `banking.*`
   referencing a tourism resource must write `tourism.Accommodation` — the
   bare form only ever means "same domain as me."
4. If a bare name matches **both** a same-domain qualified resource and a
   separately-defined bare-named resource, that is **ambiguous** — an error,
   never a silent guess (this is precisely the failure mode SD-2 named:
   two domains silently meaning different things by one name).

```yaml
# tourism.Accommodation.resource.yaml
resource:
  name: tourism.Accommodation      # qualified — canonical stored form

# tourism.search.capability.yaml (same domain)
capability:
  id: tourism.search
  output:
    accommodations: { collection: Accommodation }   # bare — same-domain shorthand, resolves to tourism.Accommodation

# banking.some-capability.capability.yaml (different domain, referencing tourism)
capability:
  id: banking.some-capability
  output:
    stay: { ref: tourism.Accommodation }             # MUST be qualified — cross-domain
```

**Storage form:** the **qualified** name is canonical wherever a resource is
*defined* (`resource.name`); bare is accepted only where a resource is
*referenced* (`ref`/`collection`/resource-typed `type`), and only ever means
same-domain. The compiler canonicalizes every reference to its qualified form
before it reaches the IR — no bare name survives compilation (`compile.ts`
`canonFor`).

## 4. What v0.2 deliberately keeps OUT

The most valuable section — argued so it is not reopened (Charter §5 Rejected Alternatives):

| Kept out | Why | Where it lives |
|---|---|---|
| `trigger` / execution initiation | need proven, **form not earned** | RQ-001 (Research) |
| `preconditions` | reduces to `failures` (×3) | ADR-0004 D-1 |
| `guarantees`, `signature` | absorbed / generated | ADR-0004 D-3/D-5 |
| `emits` / business events | wanted, never *necessary* | deferred, evidence rising |
| streaming / subscriptions | async, out of the sync grammar | MODEL_BREAKERS G (scoped out) |
| resource `states:`/`transitions:` | derived, not authored | RQ-002 |

## 5. Completeness validation

**Conjecture.** *CDL is a basis for **synchronous** business capabilities with
primitives: `id`, `description`, `effect`, `input`/`output` (`type`|`ref`|`collection`),
`failures`, `lifecycle`, `policies`, `provider`, `resource.fields`.*

**Evidence — domains that HOLD** (link: MODEL_BREAKERS):

| Domain | Expressible? | | Domain | Expressible? |
|---|---|---|---|---|
| Tourism | ✔ | | Manufacturing | ✔ |
| Banking | ✔ | | Logistics | ✔ |
| Healthcare | ✔ | | Government | ✔ |
| Commerce | ✔ | | Legal · Trading · Auction | ✔ |
| Insurance | ✔ | | Subscription · Medical-approval | ✔ |

**Failed counterexamples** (the valuable half):

| Candidate | Verdict | Why |
|---|---|---|
| `preconditions` | ❌ | reduces to `failures` — ADR-0004 D-1 |
| `guarantees` | ❌ | mixed layers |
| `signature` | ❌ derived | rendering of input/output |
| state-machine DSL | ❌ derived | RQ-002 |
| `trigger` field on capability | ❌ | never on a capability (P8) |

**Open questions — proven need, unproven form:**

| Question | Proven | Open | Tracked |
|---|---|---|---|
| Execution initiation | need (7 domains) | form | RQ-001 |
| Resource state form | need | whether P-3 fields suffice | RQ-002 |
| Proactive affordance planning | recurring `preconditions` pull | whether it ever earns entry | RQ-002 §7.2 |

## 6. Stability and rollout

1. Accept this RFC → primitives enter **Experimental** (not Canonical — Rule 11).
2. Update `cdl.schema.json` (v0.2, experimental additions) + re-cut `examples/manifests/` with a second company (`bank/`) beside `booking/` (ADR-0001 process).
3. Add these domains as **normative** canonical examples; they become semantic-regression fixtures.
4. Graduate to **Canonical** only after the compiler (RFC-0001 D-6) and real manifests exercise them.

**Independent versioning:** this is CDL `0.2`. The platform/runtime versions separately (Charter §3).

## 7. Decision registry

| ID | Decision | Rationale |
|---|---|---|
| D-1 | Promote `effect`, `failures`, `ref`, `lifecycle`, `resource.fields`, and the 5 types to **Experimental** | Met all three freeze gates (Charter §2.1) |
| D-2 | Keep `trigger`, `preconditions`, `emits`, streaming, state-machine DSL **out** | §4 — reduced, deferred, or unearned |
| D-3 | Enter at Experimental, not Canonical | Rule 11 — freeze only after compiler + real manifests |
| D-4 | `effect` axiom promoted to Constitution A-1; this RFC uses it | fundamental semantic, not RFC-local |
| D-5 | Resource state = fields; no authored state machine | RQ-002 |
| D-6 | Semantic types extracted to RFC-0005; grammar and types version separately | types evolve faster than grammar |
| D-7 | Grammar is normative in the [CDL Specification](../cdl-specification.md); this RFC is rationale | Rust Reference/RFC split |
| D-8 | Resource names: qualified is canonical storage form; bare is same-domain-only shorthand; cross-domain refs must be qualified; an ambiguous bare match is an error, never a guess | Pays SD-2 in full — closes the gap between the shipped resolver (ADD-11) and ratified grammar |
